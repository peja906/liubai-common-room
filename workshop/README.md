## 檔案與隔離

- `api.mjs`、`schema.sql`：實驗 API 與追加資料表；只對明確傳入的固定欄位處理。
- `ui.mjs`、`ui.css`：本機工坊頁面、草稿、結果未知與明確重送的操作。
- `preview.mjs`：只綁 `127.0.0.1` 的本機預覽，使用 Node 內建 SQLite 與 D1 形狀的介面。提交預設關閉，公共板可另行隱藏。
- `api.test.mjs`、`ui.test.mjs`、`review-boundaries.test.mjs`：記憶體 SQLite、合成 Request／DOM 的迴歸測試。

正式 `build-site.mjs` 與 `prepare-static.cjs` 仍採原有八個前端資產清單，沒有匯入或打包工坊。此 schema 不修改既有公共 Wiki migration，也不會自動套用至任何遠端資料庫。

## 本機檢視與測試

需要已安裝的 Node.js 24，無外部套件或 API key。以下只啟動提交關閉的本機預覽；資料庫必須是暫存目錄內以 `liubai-workshop-` 開頭的 `.sqlite` 檔案。

```sh
node workshop/preview.mjs --port 4176 --db /tmp/liubai-workshop-review.sqlite
```

預覽網址為 <http://127.0.0.1:4176>。Ctrl+C 停止，資料庫保留，不自動清除。請只使用合成資料，不要公開轉發或對外代理此 listener。

不開啟 listener 的測試：

```sh
node --test tests/*.test.mjs workshop/api.test.mjs workshop/ui.test.mjs workshop/review-boundaries.test.mjs
```

工坊測試使用真實 Node SQLite 的 `:memory:` 資料庫與 D1 形狀的測試介面；不是託管 D1。前端測試是合成 DOM／mock fetch，不是瀏覽器端到端驗證。

## 已知限制

應用層包含 8 KiB 本文上限、本文總 deadline、文字長度、固定 SQL、成功寫入頻率與總量限制。這些不限制所有抵達平台的請求，也不能防止匿名訪客耗盡共用名額。精確 Origin／Fetch Metadata 檢查不是機器人身分驗證；內容 hash 也不是作者身分或刪除授權。

隱藏公共板會在應用流程的檢查點拒絕讀取及提交，並清除前端可見公共內容；保留本機自寫草稿與結果未知的 outbox。SQL 已交付資料庫後仍可能提交，開關不能保證撤銷；此時回應為結果未知，不能說成「未寫入」。最後同步檢查後已建立／傳出的回應及外界副本無法追回，也不保證所有訪客即時清屏。

本機傳輸本文的 5 秒 deadline 從完整 HTTP headers 抵達 handler 後開始；不是慢 headers、握手或作業系統的嚴格硬時間上限。沒有證明多實例／真實 D1 的原子停用語義。文字過濾不等於逐篇內容審閱；目前也沒有逐篇隱藏、申訴及撤回處理流程。

## 證據範圍與下一個審核條件

選定回覆來源在讀取失敗後殘留，以及等待中切換隱藏狀態的兩項缺陷，已在限定的合成 DOM／API 時序範圍復驗通過。這不表示完整安全稽核或零漏洞。

工程曾提交這版的 HTTP 5/5 結果；獨立環境的 HTTP 復跑則在 listener 啟動前遭 `EPERM`，發出 0 請求、執行 0 案例。本 PR 整理不重試該操作，也不把工程結果列為獨立 HTTP 通過；原內部紀錄不隨程式公開。

匿名公共寫入仍需先完成：

1. 確認可執行的前置請求／平台用量硬上限、觸頂停用行為與成本邊界。
2. 建立逐篇不當內容處理、隱藏／撤回及回報流程，列明不能追回副本的限制。
3. 在已允許 loopback 的環境完成獨立真 HTTP 復跑；未來若擬部署，再審閱實際平台、D1 與多實例行為。
4. 對最終變更重新審閱並取得明確發布決定；草案 PR 或測試通過本身不是上線許可。
